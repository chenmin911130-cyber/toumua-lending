## 交付与范围

- 本版包含 42 张高保真页面／状态图，以及本文定义的复用页面、表单步骤和状态变体。
- 设计图使用内置 Image Gen 生成，完整提示词和修订提示保存在 `manifest.json`。这是一套待用户评审的视觉设计，不是已实现的软件。
- 客户网站、员工 Web 管理端、办公室桌面端使用同一品牌语言；桌面端复用员工页面。
- 页面语言暂定英文，评审说明为中文。
- 客户自助在线申请、在线预约、在线付款、聊天、离线资金录入不纳入本版。客户联系贷款专员共同填写申请。
- 账户恢复、回执打印、资料维护、权限呈现和错误处理是为形成完整体验提出的配套设计，不声称原 PDF 已逐项规定。
- 示例姓名、照片、日期、资产及金额只用于布局。不同图片表现不同时间或不同申请，不能拼接成真实账本或据此推导收费政策。
- PostgreSQL 现有表结构未读取；本版字段是界面设计，后续需与实际数据模型映射。

## 使用设计册

打开 `index.html`，按客户网站、员工管理端、共用账户、桌面应用筛选。点击图片可放大，详情里可填写每页修改意见，导出为 Markdown 后提供给 Codex。意见仅暂存于当前浏览器，不会自动发送。

建议反馈格式：`C03：下次还款卡片小一点，余额放到右边。`

## 复用页面与表单步骤

以下复用布局在 V2 展开为 S20、S21、S22、A07。字段与行为如有出入，以 IMPLEMENTATION_SPEC.md 和 BUTTON_FUNCTIONS.md 为准。

### S02 新增／编辑客户抽屉

- 标题 Add borrower / Edit borrower。
- 字段：姓名、称呼、邮箱、电话、地址、内部备注；借款人编号由系统生成，不手填。
- 新建时主按钮 Save borrower；编辑时 Save changes。必填要求与数据库和客户资料规则对齐，不能从示例任意推导。
- 成功后关闭表单并选中保存的客户；失败保留输入。未保存关闭时提示 Keep editing / Discard changes。
- 不提供客户资料硬删除入口。

### S04 五个步骤

1. **Borrower**：搜索既有客户，或打开 S02 新增；显示姓名、联系信息和编号确认选择。
2. **Loan details**：金额、用途、用途说明、拟定期限。草稿可不完整；继续前校验当前步骤必填项。
3. **Security assets**：资产列表，新增／编辑资产抽屉（名称、描述、照片、状态）；估值通过 S05 完成。显示未估值提示，不以客户自行填写金额替代估值。
4. **Repayment terms**：S15；首期日期、频率、期数、利息与费用规则、计划预览。具体允许的规则待实际业务映射。
5. **Review**：复用 S06 主内容区，以只读摘要呈现前四步，各区有 Edit 链接；没有经理决策面板；主操作 Submit for review。成功进入 S03 的待审批状态。

### S06 审批标签及确认

- Application 使用基本资料；Valuation 使用 S05 的只读内容；Repayment terms 使用 S15 的只读参数＋C05 型计划表；History 使用时间线。
- 最终批准前检查申请、估值、条款是否完整；图中的批准按钮是视觉样式，未满足条件时实际应禁用并解释原因。
- 批准确认：申请编号、客户、批准金额、计划摘要，Confirm approval / Back。
- 拒绝确认：说明文本框、Confirm decline / Back；提交后显示决定时间、人员及结果。
- 本版建议客户只看到对客户可公开的拒绝说明，不暴露内部备注。

### S08 贷款详情标签

- Account overview：图示概况。
- Repayment schedule：C05 的计划表，员工可查看更多业务字段；已批准条款不在这里随意改写。
- Transactions：S13 表格限定当前贷款。
- Security：S07 资产列表限定当前贷款。
- History：创建、审批、入库、放款、收款、结清、违约、归还或出售的事件时间线，含人员及时间。
- 出纳看到 Disburse loan / Record repayment，前者仅在符合条件且未放款时显示；经理、会计和所有者不复用出纳按钮。
- 已结清状态显示零余额，提示归还是否完成；违约状态提示相关处置记录。逾期不自动等于违约。

### A01 恢复流程

- 请求链接后，无论邮箱是否存在，展示统一提示：If an account exists for this email, you’ll receive a reset link.
- 有效链接：沿用 A02 密码表单，移除 Current password，显示 New password / Confirm new password / Reset password。
- 无效或过期链接：链接已失效说明＋Request a new link，返回 A01。
- 成功：Password updated＋Back to login；不泄露账户信息。
- 此流程要求后续选择邮件发送方案；当前只是设计，无邮件已经发送。

### 客户回执

- C05 打开 S13 型回执详情，去掉员工全局交易列表和内部信息。
- 显示贷款号、收款日期、收款额、方式和回执编号；只允许访问当前客户记录。
- Print receipt 纳入 V2 必须实现，打印专用客户版回执；取消打印不改变数据。

## 关键状态规范

| 状态 | 呈现与操作 |
| --- | --- |
| 首次加载 | 保持页头和结构；内容占位使用骨架，不先显示 0 元余额 |
| 没有贷款 | C03 显示 No active loan，说明已有申请可查看进度；联系 → C07 |
| 没有申请 | C04 显示 No application yet，说明需与贷款专员共同办理 |
| 无搜索结果 | 列表保留过滤条件，显示 No results 和 Clear filters |
| 申请被拒绝 | C04 状态为 Declined，显示可公开说明与联系入口；不显示后续阶段已完成 |
| 已批准未放款 | C04 显示 Approved，说明等待抵押品入库／放款；没有可用余额承诺 |
| 逾期 | 显示到期日期、未付金额和联系入口，不使用羞辱或催迫式文案 |
| 已结清 | 余额为零，显示最终收款与抵押品归还状态；无下次还款日期 |
| 已归还／已出售 | C06／S07 显示实际处置类型和日期，不把出售画成归还 |
| 表单错误 | 具体字段下说明，页面提交后聚焦首个错误；已有输入保留 |
| 处理中 | 主按钮显示 Recording… 并禁用重复点击；不得提前展示成功 |
| 成功 | 页面状态刷新，展示交易／操作编号；提供查看详情和返回入口 |
| 明确失败 | 可修复的错误说明＋返回编辑；仅确定未记账时允许重新提交 |
| 结果未知 | 不提示“失败后重试”；先查交易状态，确认未记账再重试 |
| 页面加载失败 | 保留导航，说明无法加载并提供 Retry；不显示虚假的零数据 |
| 权限不足 | You don’t have access to this page；Return to overview，隐藏业务记录 |
| 登录过期 | Session expired，跳转登录；不丢失已经服务端保存的草稿，不本地缓存敏感资金数据 |
| 记录不存在 | Record not found；回所属列表，不返回其他客户记录 |
| 离开未保存表单 | Keep editing / Discard changes，不静默丢弃 |
| 抵押品尚未入库 | S09 放款禁用并列出缺失条件，链接到入库详情供有权限者办理 |
| 余额未结清 | S11 归还禁用并说明剩余余额，不能绕过条件 |

## 角色呈现建议

原文明确了借款人、贷款专员、估值专员、经理、出纳的主要职责。所有者和会计的具体权限未逐项给出，以下为本版设计建议，开发前应落实为权限矩阵。

| 角色 | 首页／常用页面 | 可以进行的核心操作 |
| --- | --- | --- |
| 借款人 | C03、C04、C05、C06 | 查看自己的贷款、计划、进度与抵押品 |
| 贷款专员 | S03、S02、S04、S15 | 与客户填写申请，维护资料，准备条款，参与估值 |
| 估值专员 | S07、S05、S11、S12 | 估值、入库、保管、归还及处置记录 |
| 经理 | S01、S06、S08 | 批准／拒绝申请，查看业务情况 |
| 出纳 | S14、S09、S10、S13 | 放款、收款、记录现金交易和查看回执 |
| 会计 | S13、S08 | 只读核对交易及账户；本版不设计会计总账系统 |
| 所有者 | S01、S14、S13 | 概况和业务记录只读；不默认继承经理或出纳操作 |

工作台不必按每个角色重画一套外壳：贷款专员优先显示草稿／待估值；估值专员显示估值与入库待办；出纳显示可放款及到期贷款；会计优先交易列表；所有者去掉审批按钮。

## 响应式与桌面

- 桌面设计基准为 1440×1024，实际生成 PNG 保留原比例；C08 为 390×844 比例参考，不应把图片像素尺寸直接当 CSS 尺寸。
- 1024px 以上采用完整布局；768–1023px 折叠导航、表单双列转单列；767px 以下使用客户移动布局。
- 手机表格转为按日期／记录排列的信息行，必要详情展开；不能缩小字体容纳所有列。
- 手机抽屉变为全屏详情；触控目标至少 44px，固定底栏不能盖住内容。
- 桌面 Electron 使用 S 系列页面，加原生窗口控制和 D01 连接状态；Web 版不显示原生窗口栏。
- 桌面联网访问同一服务，不在本版提供独立数据库或离线资金队列。
- Web／桌面输入需要键盘导航、清晰焦点、表单标签、可读错误、状态文字及语义结构；设计图无法替代后续实际可访问性测试。

## 2026-09-16：邮箱注册与验证补充（用户确认）

本节替代早期仅通过工作人员获得客户账户的假设。公开注册创建客户身份；员工账户由管理员创建或邀请。邮箱是登录标识，注册并不自动关联已有贷款。

### 新增与更新页面

| 编号 | 页面 | 去向 |
| --- | --- | --- |
| A03 | 客户邮箱注册 | 姓名、邮箱、密码、确认密码 → A04 |
| A04 | 等待验证 | 邮件链接 → A05；重发／修改待验证邮箱 |

### 交互与状态

- 注册中：禁用重复提交，显示 Creating account…；失败保留姓名和邮箱，密码不存入浏览器持久存储。
- 邮箱格式错误、密码不符合规则或两次输入不一致时，在对应字段下提示；密码规则在实施时统一，不从图中推断。
- 邮箱已注册：使用中性提示，提供 Log in 和 Reset password，不泄露账户资料，不再创建重复账户。
- 未验证客户不得进入贷款数据页面；只能完成验证、修改待验证邮箱或退出。
- 重发：服务端限流，按钮按服务端返回的等待时间禁用，成功后提示已发送；发送失败不显示成功。
- 修改邮箱：仅在当前待验证注册会话内编辑邮箱；确认修改后撤销旧验证链接，再发新链接。
- 验证成功：A05；继续登录需要邮箱和密码，不把公开验证链接当作完整登录凭证。
- 链接过期：A05 同布局，标题 Verification link expired，主要动作 Request a new link → A04。
- 无效链接：同布局显示 We couldn’t verify this link，返回登录或重新请求；不显示任何他人账户信息。
- 已验证：显示 Email already verified，提供 Continue to login，不报不可恢复错误。
- 验证处理中／服务不可用：显示进度或 Retry，不提前显示成功。只有服务端确认成功后才展示成功态。
- 新客户第一次登录使用 C03 的 No active loan 空状态，不展示图中的示例余额。
- 已有客户贷款与新账户的关联由员工核对后建立，不仅凭姓名匹配，也不因邮箱验证就显示未经关联的贷款。

### 邮件及部署约定

- 客户前台／管理后台、后端 API 拟部署 Railway；数据库沿用 Railway PostgreSQL；桌面应用访问同一 API。
- 只有后端持有数据库及邮件服务凭据，前端不直连数据库。
- 验证与密码重置邮件由后端通过邮件服务发送；服务商尚未选择，此次只完成设计，没有部署或发送邮件。
- 验证链接需有时效、单次使用及重发失效策略；注册身份由后端固定为客户，客户端不能指定员工角色。
- 设计图由内置 Image Gen 生成；提示词及登录页修订记录在 manifest.json。旧版文档与图索引保存在 revisions/2026-09-15。

## V2 复用状态的具体呈现

- **S16 角色／权限编辑：** 复用邀请右抽屉，姓名邮箱只读；一个业务角色下拉，manage_staff/view_audit勾选；理由必填；Review changes→Confirm changes。停用、启用、撤销邀请采用带姓名邮箱和影响说明的确认框。
- **S17 关联确认／撤销：** 两列账户ID与借款人ID、姓名和核对摘要；Confirm link。撤销需经理、理由和Confirm revoke，明确客户将失去贷款访问。
- **S18 出纳申请模式：** 左原交易只读，右替代金额/日期/方式、理由，Submit request；经理模式如图；批准后出纳模式显示Post correction，复核冲正和替代两项。列表沿用S13表格，含编号、原交易、申请人、金额差异和状态。
- **S08 违约确认：** Manager点击Declare default，显示贷款、逾期上下文、政策依据、决定日期、理由；Review default→Confirm default。无政策显示未配置。
- **S08/S12 差额结算：** 显示出售收入、结算前余额、已分配金额、待处理不足或余款及正式政策提供的允许动作；先复核，Cashier最终执行。规则未确定时仅显示待结算，不画假成功。
- **S21 删除：** 列资产名和关联申请，解释只移除可编辑草稿关系，Keep asset / Remove asset。附件删除单独确认，历史快照保留。
- **S22 可提交变体：** 所有readiness通过时，琥珀条改为Ready for review，启用Submit for review，确认框显示申请ID、借款人、金额、估值、terms版本。提交后不可继续编辑。
- **全局搜索：** 顶部居中对话框，搜索字段、分类结果（姓名+编号+状态）、加载/无结果/失败状态。结果带键盘选中焦点；右上X关闭。
- **通用表单错误：** 页首错误摘要链接到字段，下方说明；保留已填内容。没有字段错误时不显示示图中的红字。
- **通用空状态：** 标题说明当前无记录，有可行动下一步；搜索无结果提供Clear filters；读取失败提供Retry并保留导航。
- **邮件链接失效：** A05/A07沿用中心单面板，分别显示Expired、Invalid、Already verified或Service unavailable，提供对应清单动作；不能一律画成功绿色勾。
- **回执打印：** A4白底，品牌、回执号、日期、借款人、贷款号、类型、金额、方式、经办者和更正关联；客户版去内部字段，底部页码，长内容自然分页。
- **桌面重连：** D01保留应用壳；断线不显示陈旧金额为实时数据；重连先确认登录与未决交易，再恢复当前业务页。
