# 外部依赖与已采用的设计决定

## 尚需实际信息，不能从图中猜

| 依赖 | 影响 | 现在如何继续 |
| --- | --- | --- |
| Railway PostgreSQL schema及测试连接 | 表列映射、现有数据、唯一约束 | 先做本地隔离模型和API适配；拿到连接后只读检查，产出映射与非破坏迁移 |
| 正式利息公式、费率/周期、费用、舍入、计提、还款分配顺序 | 计划、余额、结清、更正重算 | 接口已实现；`CALCULATION_POLICY=demo` 使用标明 demo 的单利占位（默认 21% p.a.，可用 `DEMO_ANNUAL_RATE_BPS` 改）；测试仍用零利息 fixture；客户确认正式公式后替换，不要把 demo 当成办公室政策 |
| 抵押品“明显高于贷款”的可执行规则 | 估值通过条件、经理审查 | 显示金额对比及经理判断，不编造2倍/3倍门槛；数字门槛待确认 |
| 提前/部分/超额还款、回溯记账、节假日到期处理 | quote与账本分配 | 设计支持明确政策响应；不支持的组合返回可解释错误 |
| 违约依据、出售条件、余款/不足额、结清后更正策略 | 违约和最终结算 | 明确经理决定与待结算状态；不自动免除债务或处置多余款 |
| 邮件服务和发送域名 | 验证、找回、员工邀请 | 使用邮件适配器和本地收件箱完成开发测试；真实发送等待配置 |
| 私有附件持久存储 | 抵押品照片 | 通过存储接口实现，开发可用隔离持久目录；生产不能仅使用容器临时盘 |
| 客服电话、邮箱、地址、营业时间 | C07的真实联系入口 | 内容配置化，缺失显示说明；不能填虚假电话和邮箱作为上线数据 |
| Electron目标系统和分发方式 | 最终安装包及签名 | 先当前macOS开发验证；Windows安装/签名在目标确认后实机验证 |

这些不阻止搭建工程、完成界面、认证、角色、关联、草稿和绝大多数控制逻辑；会阻止声称生产资金业务已可用。开发报告逐项标记 blocked_external，不能简单删掉相关功能。

## 已采用的设计基线

- 单一客户账户对应一个borrower，可看多笔贷款；不支持家庭成员共享账户。
- 注册只创建Customer；员工由管理员邀请；Owner不是超级管理员。
- 一个员工一个业务角色，管理/审计权限独立授权；默认职责分离。
- 客户个人资料只读，需要更改贷款资料联系员工；不引入未设计的自主换邮箱流程。
- 通知、全局搜索、回执打印、交易CSV导出纳入V2；不是占位图标。
- 资金交易写入由出纳执行；更正须经理审批且保留原流水。
- UI默认英文，评审/交付说明中文；不默认为已实现多语言。
- 无离线资金录入、无在线支付、无独立预约/聊天系统。
- 认证期限和字段长度为项目实施默认，不是原PDF中的正式业务政策；见IMPLEMENTATION_SPEC。

## 必须避免的“看起来完成”

按钮只弹toast、列表使用固定数组、打印空白、上传仅内存预览、通知固定红点、角色只靠隐藏菜单、刷新数据丢失、资金错误后换key再提交、所有者默认拥有全部写权限，均不满足交付。
