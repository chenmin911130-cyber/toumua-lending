# 给 Cursor 的执行任务书

## 可直接复制的任务

```text
请在当前项目实现 Toumu’a COMP721 贷款管理系统。
先阅读 PROJECT_PLAN.md，以及 design/v2 下的 README.md、IMPLEMENTATION_SPEC.md、BUTTON_FUNCTIONS.md、ACCEPTANCE_TESTS.md、DECISIONS.md、manifest.json 和设计图。

使用 TypeScript：React/Vite Web、NestJS API、Electron 桌面。客户与员工使用不同界面；员工管理端也是前端，调用同一后端。沿用现有 Railway PostgreSQL，先检查现有 schema 并建立映射，不得默认清空、重建或覆盖现有数据。数据库、邮件密钥只放后端环境变量。

按 controls.json 的稳定编号实现全部控件，包括导航、搜索、筛选、通知、上传、确认、打印、分页、空状态、失败重试、权限不足和断线恢复。图里金额、姓名只是展示样例。每个控件记录实现文件及对应测试；未实现不能标记完成。不要用空事件、假成功 toast、alert、只有模拟数组的界面或无效链接充当功能。

执行顺序：工程与 API 契约 → 认证与权限 → 客户资料和账户关联 → 申请、估值与条款 → 审批、入库 → 放款、还款、交易更正 → 归还、违约出售 → 客户门户、通知、审计 → Electron → 全面验收。每个模块完成前后端闭环再推进。

设计文档中的 API 与数据实体是目标契约，不是声称现有数据库已经如此。先用本地隔离数据库实现和测试；有连接信息后只读检查现有 schema。输出 database-mapping.md 和非破坏性迁移方案，不能擅自对线上运行迁移。生产利率、费用、分配顺序、违约标准尚未提供，按 DECISIONS.md 处理；测试政策只能在测试环境使用，不能冒充正式政策。

交付可运行代码、.env.example、启动及测试命令、OpenAPI、schema 映射、测试报告和桌面打包脚本。逐项更新 controls.json 的 implementation_status、implementation_refs、test_refs；实际运行通过后再更新 test_status。最终报告列出完成、失败和外部依赖阻塞项。不要把“页面可打开”当成“业务已实现”。
```

## 多工具协作边界

用户可以让 Cursor 实现代码，同时在 Codex 继续修改设计。约定 `design/v2/` 为设计基线，Cursor 实现放在 `apps/web/`、`apps/api/`、`apps/desktop/`、`packages/contracts/`、`packages/ui/`、`tests/`。设计有变化以独立修订记录交付，避免两个工具同时改同一文件。不要运行多个会同时迁移同一数据库的进程。

建议任务拆分：

| 批次 | 产出 | 通过条件 |
| --- | --- | --- |
| 01 | 工程、路由、统一控件、API 契约、数据库映射 | 三端启动；全量路由清单；现有 schema 差异明确 |
| 02 | 注册、验证、登录、重置、邀请、权限 | AUTH 用例通过；跨客户访问被拒绝 |
| 03 | 借款人、关联、申请、估值、上传、条款 | 草稿刷新可恢复；提交前置条件完整 |
| 04 | 审批、入库、放款、还款、回执、更正 | 钱款幂等与并发测试通过；余额由服务端计算 |
| 05 | 归还、违约、出售、审计、通知、客户全部页面 | 两条业务全流程通过；无死链接 |
| 06 | Electron、响应式、可访问性、部署准备 | 安装启动、断线恢复、打印及浏览器回归通过 |

## Definition of Done

- 每个 control ID 对应可运行的行为；共用控件在每个适用页面实例化，不能只测试一个孤立示例。
- 所有写操作经后端鉴权、验证并持久化；刷新后仍正确。客户读接口只返回本人数据。
- 所有贷款数值由经过验证的计算服务产生；只在明确标注的开发演示中使用 fixture。
- 单元、数据库集成、端到端测试均有结果证据；未运行标为 not_run。
- 资金重复提交、并发、超时、跨端恢复、账户停用立即失权均通过。
- 前端构建、API 构建、桌面构建通过。目标操作系统未确定时，只声明已实际验证的平台。
- 不在本阶段自动发布生产系统、不发送批量真实邀请、不改写生产数据库。

当前交付是设计与实现规范，尚无业务实现；所有控件初始状态均为 `not_implemented`。
